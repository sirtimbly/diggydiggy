# Diggy

<!-- impeccable:product-schema 1 -->

## Platform
web

## Stack
Vite and React organize the interface into components, with CSS and a small Canvas sprite renderer. Browser-local projects work independently. Optional shared projects use Cloudflare Workers, SQLite Durable Objects, and PartyServer WebSockets.

## Users
Developers and team leads exploring current work together.

## Product Purpose
Make a project visible as an excavation. Show known work, uncertain scope, order of operations, and where developers are working without implying deadlines or duration.

## Capabilities and Constraints
The header's New project action creates and opens a blank shared excavation with its own private invite link, without sample work, crew, dividers, or excavations. The current local or shared project remains intact, and sign-in is required to create or edit projects. Creation shows a busy state; failure leaves the current project open with a dismissible error and retry guidance. An empty excavation says “Fresh ground” and offers Add your first block. Only the demo project shows a demo badge. Share uses a chain-link icon in the header and invite actions; its private-link access behavior is unchanged.

The board toolbar places Add block immediately after Undo and Redo, followed by the zoom and reset-view controls. The former project action strip is removed; the demo badge belongs to the toolbar. Mobile uses two toolbar rows and retains the project name, Cleared, Phases, history, Add block, zoom, and reset-view controls.

Click the project name in the desktop header or board toolbar, or click the surface sign, to open the native Edit project modal. Project name is required and Sign subtitle is optional; each accepts up to 80 characters. Save changes trims and commits both fields together as one undoable shared edit. Cancel, the close button, or Escape discards the draft; moving focus does not save. Remote updates cannot replace an open draft. Details persist locally and sync for shared projects. New projects and older unnamed projects display “Untitled project”; the initial demo is named “The next release.” The timber surface sign always displays the project name with the optional subtitle below; a blank subtitle omits the second line. Long sign text truncates with an ellipsis and exposes the full text in a tooltip. The sign sits clear of the default crew tray.

Decorative scenery includes a blue porta-potty beside the surface fence and scattered dinosaur remains 60 terrain units below the surface. Deeper discoveries include a helmeted dwarf with a braided copper beard and crooked grin digging at 180 units and a winged, horned balrog in a soot-dark rock cave at 240 units. The balrog breathes and shifts through an eight-pose idle cycle, flexing its wings, turning its head, and swaying its arms and whip above flickering coals and rising embers. These scenes stay anchored in world coordinates through panning and zooming, without project data or interactions. Underground discoveries appear only in soil: full work-block footprints, including uncertain regions, and excavated cavities or shafts hide them. The dwarf digs with a six-pose pickaxe cycle and impact sparks; both creatures and the flames use stepped pixel animation, remain still with reduced motion, and pause while the page is hidden.

The excavation occupies the full available workspace. A small collapsible worker palette starts at the top left. Drag its Crew header to move it out of the way within the canvas, independently of terrain pan and zoom. The focused Move crew palette control supports 8px arrow-key moves, 32px with Shift, and Home to reset; Escape cancels an active drag. Its normalized browser-local position survives reload, viewport resizing, and expanding or collapsing the tray, without project sync or undo history. Manage crew, collapse, and digger assignment controls retain their behavior. Phase captions avoid the tray at its current position. Its keyboard-accessible Manage crew control opens a modal with active and archived rosters. Create diggers, edit names and helmet/shirt/skin/hair colors, choose no hair or short/medium/long hair, and toggle glasses and headphones independently. A large live preview reflects the draft; Save commits it and Cancel discards it. The form fits mobile screens and scrolls on short viewports. Archive or restore members; archiving removes current assignments atomically, while restoring makes the digger available for new assignments. Crew data belongs to each project, saves and syncs per field, and participates in undo/redo. Older crew records use defaults for optional appearance fields. Clicking a block opens compact nonmodal details beside it; labeled color swatches at the top save changes immediately, with undo and live sync. The full edit/create form also starts with those swatches and retains Save/Cancel semantics. Progress, uncertainty, and assignments are immediate, with size and dependencies in an expandable section. Close by Escape, the close button, or clicking outside. The same popup stays within the mobile screen; there are no permanent inspector or crew sidebars.

Work blocks offer ten colors: Amber, Moss, Lilac, Coral, Blue, Rose, Peach, Lemon, Teal, and Slate. The browser remembers the last explicit color choice from a creation form or existing block details, even if the form is later canceled. Add a block, Add your first block, and the empty-soil plus start with that choice across forms, reloads, and projects, falling back to Amber. A source block’s attached plus starts with the source color; merely opening it does not change the remembered choice, while choosing a swatch there does. This preference stays separate from project sync and undo/redo. If browser storage fails, the current tab keeps the choice in memory.

Drag work blocks through soil. Move diggers onto blocks, including several diggers on one block, subject to the project’s maximum placements per digger. The maximum defaults to two for new and older projects and can be set from one to eight in Manage crew using the Placements per digger number field with visible native up/down steppers and Save limit. The field requires a whole number from one to eight; clearing it leaves a blank draft while editing, and a successful explicit save normalizes the displayed number. Lowering it below anyone’s current assignments names the affected crew and leaves assignments intact; the user must remove assignments before saving a lower limit. The setting saves locally, syncs with the project, and supports undo/redo; incoming updates wait while its draft is dirty. Crew buttons and the active roster show one pixel LED for each available placement, dim when unused and green when assigned. Accessible labels and tooltips retain exact assignment counts. Represent unknown scope with an adjustable vertical dithered band in the block color: higher uncertainty enlarges the obscured region while a faint 28% tint preserves the full estimated footprint. Soil texture shows through that tint; known material and the bottom rim remain opaque. At zero unknown, the face has no mask. Preserve readable task labels. Represent deliberate progress with cracks and excavation. Depth indicates sequence, never time.

Block details include a Blocked switch for unfinished work, before progress. Turning it on closes the site with a striped pixel construction barrier and a slowly rotating amber beacon that casts pixelated light across the surrounding soil, fading into deep shadows, and removes all assigned diggers in the same undoable edit. Blocked work cannot accept diggers or advance progress. Turning it off removes the barrier and leaves the site unassigned, ready for deliberate reassignment; saved progress, dimensions, uncertainty, and dependencies stay intact. The manual flag saves locally, syncs, and survives reload and undo/redo. It is separate from waiting on prerequisites or buried work. The block’s accessible description and details explain the closure; reduced motion keeps a steady light pool and a still reflector. Signed-out viewers can inspect the state but cannot change the switch. Phase captions avoid the barrier.

Live work blocks show their number, title, and any progress percentage without routine status badges. Ready work keeps its chosen stone color; buried work, prerequisite waiting, and manual closure subtly mute the stone face and the number/title ink and backing together. Diggers, crew, presence, and barrier colors retain their normal treatment. Working sprites and the closure barrier remain visual activity cues; accessible block descriptions and details explain availability. Availability updates during drag previews. Completed work keeps its Cleared label.

Stone faces have one 4×4px world pixel cut from every corner, with square stepped corners and 4px inset bevels. The face, bevels, texture, and cracks share the uncertainty mask; labels and controls remain readable outside it. These visual cuts preserve the full rectangular collision, selection, and control bounds.

Blocks form a contact stack of actual 2D rectangles. Dragging reorders work and snaps to contact edges. Collision and selection bounds match the colored box, with no external uncertainty padding. Uncertainty affects only the visible face. Extraction leaves a persistent empty space; completed bodies stay reserved during later rearrangement and neighboring cavities form one hole. The excavation depth follows content and layout, with a minimum of 1160px; work and placement previews can extend it. It also expands sideways without a fixed column limit, with edge scrolling while dragging sideways or within the available depth. Known block width and height can be resized from all four edges and corners, independently of uncertainty, with masonry reflow and saved custom dimensions. Double-clicking a left/right side handle, or pressing Enter while it is focused, grows that edge to the nearest outward seam of a live block above or below. The opposite edge and height stay fixed. Alignment is exact, cannot pass through work or excavated ground, respects the maximum width, and saves as one undoable shared edit.

Hovering or focusing a live work block reveals a plus docked to its bottom edge; selecting a block also reveals it on touch screens. The plus opens the normal creation form with the source block's color and width. Saving inserts fresh work below the source, with zero progress, no assigned diggers, and no prerequisites, and reflows later work around reserved excavations. Hovering empty soil reveals a column plus at the next available depth, accounting for current bodies and reserved holes; gaps too narrow for a block offer no plus. This opens the same form with the remembered color selected, falling back to Amber, and saves work in that column. These placements retain a minimum depth through later reflow, save locally, sync, and participate in undo/redo; moving the block releases its retained depth. Hover state stays local. Cancel leaves the project unchanged, and the existing Add a block action remains available for keyboard and touch use.

Display block numbers without the stored prefix or leading zeros: DIG-01 appears as 1 on task faces, in details, in the Cleared list and revealed card, and in screen-reader labels. Stored IDs and codes remain unchanged.

New and edit block forms focus the title immediately. While the canvas is idle, N opens the creation form below the last-created unfinished block, falling back to the selected unfinished block and then the normal untargeted creation flow. A targeted form inherits that block’s color and width. N follows the existing sign-in requirement; canceling leaves the project unchanged.

G opens a small Go to block form near the bottom center of the canvas and focuses its numeric text field. Enter a stable block number, including multiple digits, to jump after a 650ms typing pause, or press Enter or Go immediately. A missing number leaves the form open with an inline error; Escape, Close, or clicking outside cancels it. Navigation selects and focuses the block, centers its world footprint, and fits the view between 60% and 100% zoom. Completed work reveals its original cavity card using the existing browser-local visibility preference and stays completed. Reduced motion makes the scroll immediate. N and G ignore text entry, composition, held-key repeats, Command/Ctrl/Alt combinations, open dialogs, menus and forms, and active drag or pan gestures. Signed-out visitors can use G.

The toolbar's Cleared menu searches completed work by title or number, with separate controls for details and canvas visibility. Revealing a block brings its original cavity into view and shows a muted dashed card with a checkmark, Cleared label, and 100% status. It remains completed and keeps its excavation reservation, without workers, movement, resizing, or dependency controls. Details can deliberately reopen work. Visibility is a browser-local preference saved separately per project, survives reload, and does not sync or enter undo history; reopened or deleted blocks lose that preference. Search is transient.

The excavation can be panned with middle-button drag or Space plus left-button drag, including over work blocks. Horizontal panning extends into fresh ground. Vertical scrolling and panning stop at the content-derived world depth; they do not generate more empty ground. Editing text retains normal keyboard behavior. Hold Command or Ctrl while scrolling over the excavation to zoom from 60% to 135% around the cursor. Ordinary scrolling remains unchanged. Modified scrolling is captured even at the zoom limits, and zoom pauses during active drag/pan gestures or while Edit project is open. Zoom affects only the local view, without saving, syncing, or entering undo history.

The toolbar's Phases menu adds named phase or milestone dividers in five muted colors: Sand, Sage, Mist, Heather, and Clay. Menu entries and canvas captions/lines open a nonmodal editor for naming, recoloring, or removal. Drag lines or captions in either axis, or nudge focused captions by 8px with arrows and 32px with Shift. Escape cancels a drag; a completed drag is one undoable edit. Captions repeat across clear soil and use wrapping or an above-course leader when space is tight, reserving stone, digger walking ranges, the crew tray, other captions, and excavation markers. Text remains at least 12px on screen at minimum zoom; long names may truncate with a full-name tooltip. Dividers are optional project annotations that persist locally, sync per field, and survive reload and undo/redo. They never alter masonry, dependencies, progress, or imply dates.

Overhead stone occludes lower work. Vertical shafts open only above exposed top-face intervals and join completed cavities. Diggers stand in this empty space on reachable surfaces; buried assignments wait until the way is clear. Fractures begin at the edges and grow inward like lightning, splitting into connected smaller branches as progress rises; they do not simply get thicker.

Dependencies can be drawn from a prerequisite’s lower connector to dependent work. A block may have multiple prerequisites, cycles are rejected, and every dependent footprint must stay below its prerequisites during placement and resizing.

Diggers use 40×48 pixel sprites with larger faces and retain their appearance through every pose and both facing directions. They have independent work rhythms, with occasional coffee sips, phone pauses, and short walks along their own exposed ledge. These are ambient character animations only; they never advance reported task progress. Reduced motion keeps characters stationary.

## Brand Commitments
Pixel art, earth and stone textures, colorful work blocks, and diggers with animated pickaxes. The brand pairs the Silkscreen wordmark with a centered pixel shovel: copper D-grip, timber shaft, brass collar, and shaded teal steel blade. The same shovel asset serves the header and favicon.

## Open Decisions
The user confirmed manual progress; animation shows activity only. Google and GitHub sign-in identify the current browser session and are required for all project changes, including local drafts, names, subtitles, blocks, crew, phases, creation, and undo/redo. Signed-out visitors can inspect and navigate without editing. Shared viewing access comes from an unguessable private invite link; editing requires both the link and a valid account session. Account sign-in alone does not grant project access. Signing out preserves saved work and viewing access while stopping edits, including on already-open WebSockets. The interface starts read-only until the account is confirmed; failed session checks fail closed. Shared commits save live; pending edits replay after reconnect, and conflicting changes require an explicit choice. Individual roles and live drag/cursor previews are not implemented. Shared projects publish live collaborator presence separately from project data: signed-in people appear by verified name with a provider photo or initials, anonymous viewers receive one of twelve underground creature names with a matching chunky 16-pixel avatar, and multiple tabs from one signed-in person share an avatar and color. The avatar stack sits beside the save status and opens a participant list. Other sessions’ selected blocks retain matching colored outlines and show circular initials markers with matching cursor arrows pointing into the block, including anonymous viewers. The first circle is centered on the block’s bottom-right corner, half overhanging both edges; up to four distinct people appear side by side. Full names remain available to screen readers, the decorative markers do not intercept pointer input, and inverse scaling keeps them readable when zoomed out. Inactive tabs clear their selection and show an Away status while avatars remain fully opaque, and disconnected or stale sessions disappear. Presence never changes revisions, project history, or editing permissions. Resizing and moving sync authored dimensions, pins, and order; derived packing coordinates are recomputed to avoid false conflicts. Reconnect receipts clear pending edits even at the current revision. Genuine competing field edits still pause for an explicit recovery choice with a backup.

The bottom toolbar centers an optional project color legend. Signed-in editors can customize the ten block colors and give each a label of up to 32 characters; blank labels stay out of the legend. Labels replace the default names in both block color pickers. Save legend commits the changed entries together; Cancel and dismissal discard the draft. Anonymous viewers see the saved legend without editing controls. Color choices and labels belong to the shared project’s `colorLegend` object, survive reload, and support undo/redo. Existing blocks keep their slot IDs and follow that slot’s color.

Opening a project plays a short, skippable pixel intro: a sky title holds briefly, the camera descends through the grass, and dirt bursts upward to reveal the loaded excavation’s live block footprints, open shafts, and cleared cavities. The animation waits for actual project data, hands off to the existing workspace, and never changes saved work. Reduced motion uses a brief fade with no camera pan or particles. Failed shared loads offer retry and a route to the local project.
